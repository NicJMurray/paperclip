3. Open public links where tools permit. For links, copy the source's own headline and description verbatim: prefer the article's visible headline or `NewsArticle.headline`, then its Open Graph title; use the publisher's standfirst/deck, structured-data description, or meta description. Decode HTML entities and normalise whitespace without changing wording or tone. Store the full source headline and description when available; if abridgement is necessary, use an unchanged excerpt ending at a sentence or phrase boundary with an ellipsis. Do not generate replacement headlines, summaries or commentary. If the source has no description, leave `summary` empty. For inaccessible links, use the sender's `shared_title` verbatim and leave `summary` empty when the link is identifiable; hold ambiguous links. Do not claim to have read an inaccessible page. For standalone images or notes without a source headline, use a brief factual label if needed. Assign one category and 2–5 concise lowercase tags. Prefer `articles`, `tools`, `memes`, `images`, `videos`, `reference`, `notes`, `other`. Add categories sparingly only when needed.
4. For an image, view `image_preview` (base64 JPEG) through image-capable tools when available. An image shared alongside a URL may be a site icon: categorise the linked source and preserve its headline/description, rather than describing the icon as article content. If more detail is needed, fetch `image_chunks.data` for this item ordered by `part` and reconstruct the base64-decoded pieces in a private temporary workspace. Do not publish raw previews to obtain image analysis. If image inspection is unavailable and the supplied text does not establish what the image is, set `status='held'`, with a brief `review_note`, instead of inventing its content. Do not expose private imagery or metadata in a report.

AND status = 'pending'`: set `title`, `summary`, `category`, `tags` (a JSON string array), `status='published'`, `published_at` to current UTC ISO time, and `review_note=NULL`.
